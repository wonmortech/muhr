# Huquqiy holat: Muhr Oʻzbekistonda nima qila oladi va nima qila olmaydi

> **Bu yuridik maslahat emas.** Quyidagi "mumkin / mumkin emas" boʻlimi bizning tahlilimiz, uni yurist yozma tasdiqlashi kerak. Havolalar **2026-11-13** da ochib tekshirilgan. Ikkilamchi manba shunday deb belgilangan.

## 2. OpenTimestamps isbotining maqomi

- OTS isboti RFC 3161 yoki eIDAS maʼnosidagi "malakali vaqt tamgʻasi" emas. Peter Todd: isbot maʼlumot taxminan blok vaqtidan oldin mavjud boʻlganini koʻrsatadi; muallif, haqiqiylik yoki yagonalikni isbotlamaydi ([petertodd.org](https://petertodd.org/2016/opentimestamps-announcement)).
- Vendor manbasi (ikkilamchi) OTSʼni rasmiy vaqt tamgʻasi bilan birga ishlatishni maslahat beradi ([getproofsnap.com](https://getproofsnap.com/posts/how-to-verify-opentimestamps-ots-file-bitcoin-blockchain-2026.html)).
- Oʻzbekistonda ommaviy RFC 3161 TSA xizmati topilmadi (E-IMZO sahifasi va qidiruv, 2026-11-13).
- **Xulosa:** Muhr isbotini doim "**qoʻshimcha, mustaqil tekshiriladigan dalil**" deb taqdim etamiz. "Notarial tasdiq", "sudda qabul qilinadi" degan vaʼda yoʻq.

## 3. Mumkin / mumkin emas (bizning tahlil, yurist tasdiqlashi shart)

| ✅ Mumkin (ehtimol, litsenziyasiz) | ❌ Qilmaymiz | ⚠️ Kulrang zona |
|---|---|---|
| Ochiq kod, tadqiqot, maqolalar | Boshqalar uchun kalit yoki kripto-aktiv saqlash | Oʻz OTS kalendarini yuritish: Bitcoin komissiyasi uchun BTC sotib olish kerak, rezident buni faqat litsenziyali provayder orqali qila oladi. **Yechim:** faqat ochiq kalendarlar |
| Faylning **hashini** ochiq OTS kalendarlari orqali muhrlash: studiya ham, foydalanuvchi ham kripto sotib olmaydi, saqlamaydi, toʻlamaydi | Kripto-aktiv sotish, almashtirish, brokerlik | Isbotni sud yoki notarius uchun reklama qilish (qilmaymiz) |
| Somda pullik API, odatiy dasturiy xizmat sifatida (Payme/Click) | Rezidentdan kripto toʻlov qabul qilish (PP-3832, 6-band) | |
| EIMZO / PKCS#7 imzosini faqat **koʻrsatish** | Token yoki stablecoin chiqarish | |
| Telegram bot (Mini App emas) | Asoschining ish beruvchisiga tegishli biror kod, maʼlumot yoki ichki tizimni ishlatish | |

**Maʼlumotlar:** serverda faqat hash saqlanadi. Fayl nomi ixtiyoriy va brauzerda qoladi. Qisqa maxfiy matnni hashdan taxmin qilishning oldini olish uchun brauzerda tuzli (salted) hash rejimi boʻladi, tuz foydalanuvchida qoladi.

## 4. Yurist uchun savollar (Muhrʼga tegishlilari, yozma javob kerak)

1. Hujjat **hashini** ochiq OpenTimestamps kalendarlari orqali Bitcoinʼga muhrlash PP-3832 yoki ZRU-899 maʼnosida "kripto-aktiv aylanmasi" yoki litsenziyalanadigan faoliyat hisoblanadimi? Studiya ham, foydalanuvchi ham hech qanday kripto-aktiv sotib olmaydi.
2. Shunday xizmat uchun somda pullik API sotish odatiy dasturiy xizmatmi? U IT Park faoliyat roʻyxatiga (Qaror 589, 2-ilova) kiradimi?
3. ZRU-1003 (raqamli dalillar, 2024-11-21) boʻyicha Muhr isboti (hash + Merkle inclusion proof + Bitcoin bloki) sudda qanday maqomga ega boʻlishi mumkin? Uni qanday taqdim etish toʻgʻri?
4. EIMZO imzosini faqat koʻrsatish (kriptografik tekshirmasdan) va "kriptografik tekshirilmadi" deb belgilash ZRU-793 boʻyicha biror talabga tushadimi? Ildiz sertifikatlarini ommaviy olish va ishlatish mumkinmi?
5. Faqat hash va (ixtiyoriy) fayl nomi saqlansa, ZRU-547 boʻyicha shaxsga doir maʼlumot hisoblanadimi? Server chet elda boʻlsa nima talab qilinadi?
6. Asoschining asosiy ish joyi bilan: shaxsiy open-source loyihada ochiq standartlar (PKCS#7, CMS) bilan ishlash manfaatlar toʻqnashuvi yoki IP shartlariga tushadimi? Ish beruvchidan qanday yozma ruxsat kerak?
7. Loyiha qaysi yuridik shaxs nomidan yuritilishi kerak (jismoniy shaxs, YaTT yoki MChJ), va Apache-2.0 litsenziyasi bilan kod nashr qilish uchun nima talab qilinadi?
